# Mehrsprachigkeit

Die Website verwendet eine kleine, frameworkfreie i18n-Infrastruktur. Sie wird über den gemeinsamen Header auf allen Portal-, Tools-, Guides- und Arbeitsblattseiten geladen. Das hält die GitHub-Pages-Pfade stabil: Unterseiten müssen keine eigenen relativen Pfade zu Sprachdateien kennen.

## Aufbau

```text
shared/
├── site-header.js       # bindet i18n.js zentral ein
├── i18n.js              # Erkennung, Laden, Fallback und Umschalter
└── lang/
    ├── de/{common,navigation,pages}.json
    ├── en/{common,navigation,pages}.json
    └── fr/{common,navigation,pages}.json
```

Deutsch ist die Fallback-Sprache. Beim ersten Besuch gilt `?lang=…`, danach die gespeicherte Auswahl in `localStorage` (`language`), anschließend die Browser-Sprache und zuletzt Deutsch. `?lang=en`, `?lang=fr` und `?lang=de` speichern die Auswahl ebenfalls. Bei einem Ladefehler bleiben die deutschen HTML-Fallbacktexte sichtbar.

## Einen Text übersetzen

Der deutsche Text bleibt im HTML stehen und erhält einen Schlüssel:

```html
<span data-i18n="common.buttons.more">Mehr erfahren</span>
<input data-i18n-placeholder="pages.home.searchPlaceholder" placeholder="Suchen ...">
```

Unterstützte Attribute sind `data-i18n-placeholder`, `data-i18n-title`, `data-i18n-aria-label` und `data-i18n-alt`.

Danach denselben verschachtelten Schlüssel in **allen** drei passenden Dateien ergänzen, zum Beispiel in `shared/lang/de/common.json`:

```json
{
  "buttons": {
    "more": "Mehr erfahren"
  }
}
```

Die englische und französische Datei müssen die identische Key-Struktur haben. Die Laufzeit nimmt bei einem fehlenden Zielsprachenwert automatisch den deutschen Wert; fehlt auch dieser, bleibt der vorhandene HTML-Text unverändert.

## Eine Sprache ergänzen

1. Drei Dateien unter `shared/lang/<code>/` anlegen und die Struktur der deutschen Dateien exakt übernehmen.
2. Den Code in `LANGUAGE_CONFIG` in `shared/site-header.js` ergänzen, etwa `es: { name: "Español", flagClass: "es", labelKey: "common.language.spanish" }`, und die passende Flaggen-CSS-Klasse ergänzen. Der Umschalter erzeugt seine Optionen aus dieser einen Konfiguration.
3. Den Sprachbezeichner in allen `common.json`-Dateien ergänzen.

Keine Produktnamen, URLs, Dateinamen, Code-Beispiele oder Fachbegriffe automatisiert übersetzen. Die globale Navigation sowie die erklärenden Texte und Steuerelemente der Startseite sind bereits zentral übersetzt. Umfangreiche eigenständige Guide- und Tool-Inhalte werden bewusst pro Seite migriert, damit fachliche Texte nicht durch eine automatische Übersetzung verfälscht werden.
